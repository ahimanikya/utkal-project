# From knowledge to stories

The Founder authorized continuing the next 500 items without routine permission requests on 1 October 2026. This increment organizes a frozen set of 500 existing records for editorial work and produces two connected illustrated food stories. It does not declare 500 research assignments complete or replace human authority.

## One KB, a useful view

The [selection](../records/editorial-workbench-selection.json) preserves the original 500 identities. The [generated assessment](../records/editorial-workbench.json) records source and subject connections, metadata gaps, existing website paths and next actions. Executable code and a portable read-only interface live in `projects/editorial-workbench/`; their data remains in this bundle. The interface is excluded from the public tourism website.

The batch contains 361 source identities, 64 people, 48 works, 23 food concepts and Chilika, Konark, Debrigarh–Hirakud and Koraput. A source identity is not an independent publication count. New matching records from concurrent research are listed separately rather than silently changing the frozen selection.

## What the assessment means

Connections come from declared source IDs, explicit footnotes, structured preparation accounts and unambiguous URL matches. A common registry URL can contain several publications: such matches are flagged for comparison, not silently linked to every subject. Existing website routes mean code exists; release evidence establishes live publication.

Each record has a next action grounded in its saved metadata or existing research question. A missing publisher field does not mean a publication has no publisher. A retrieval limitation may be historical and must be read alongside later capture evidence. Flags identify work to inspect; they do not certify a source as unreliable or a claim as false.

Rasabali’s curdling discrepancy and Magji’s sugar proportions remain explicit. Local practice, Odia terminology, source rights, editions, current visitor arrangements and final human judgment are not replaced by this assessment.

## Working loop

Read an existing record and its source passage. Compare the website treatment. Resolve a specific missing question, prepare an illustrated narrative, connect it to useful discoveries and the visitor’s journey, then record the actual review and release state. Keep source and image credits compact at the end of the public page, with qualifications in the story where they change meaning.

Do not create placeholder public pages merely because a KB record exists. Do not treat a generated readiness flag, passing test or repeated source URL as human approval or corroboration. Update canonical data and regenerate the view; filtered downloads are working copies.

## Design and access

The workbench uses the Utkal sea/stone/ivory direction, a responsive grid, readable next-action cards, keyboard-accessible native controls, pagination and a live result count. Filtering is local. It makes no network calls until a user follows a source or repository link. It neither collects user information nor provides authenticated access to private information; only already-public repository records belong here.

Browser layout and assistive-technology review remain unverified because the browser tool’s administration-policy check failed. Programmatic integrity and filter tests are different evidence.
